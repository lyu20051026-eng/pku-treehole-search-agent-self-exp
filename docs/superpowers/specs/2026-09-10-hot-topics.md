# 近期树洞热点总结设计

已在需求对话中确认：终端 agent.py 模式 4「热点实时推送」，单次执行；默认 24 小时，可选 72/168 小时。扫描时间窗口内候选，默认导出最多 30 个入选帖（HOT_TOP_POSTS 可调）及评论，DeepSeek 总结约 5～10 个话题；不足时不凑数。不分析老帖重新变热，不新增 Web 或邮件入口。

## 数据证据
用户提供的实际响应确认：无 keyword 的 GET /chapi/api/v3/hole/list_comments 可取得列表；pid/timestamp 标识帖子；likenum 为收藏，praise_num 为点赞，reply 为评论计数；comment_total 经真实联调证实为预览分页提示，不用于评分或完整性判断。GET /chapi/api/v3/comment/list 参数 pid/page/limit/sort=0/comment_stream=1，响应 code=20000/data.list/data.total。cid 为评论 ID，comment_id 为父评论 ID，quote 可为对象或空数组，name_tag/is_lz 为帖内匿名标签和洞主标记。页面计数与接口 total 可不一致，缺失父评论不推断删除原因。

## 采集与算法
新流程使用独立的限速、timeout=(10,60)、至多 3 次重试、429/5xx 退避，不使用搜索的 24 小时缓存。扫描上限默认 5000 帖、每页 30、最多 200 页；按时间过滤/ID 去重。鉴于列表排序未被证明，在没有可靠边界证据时不因单个旧帖停止；接口 total 经真实联调证实为随页码增加的分页提示，不作为结束条件。空页结束枚举；非置顶时间序列持续倒序且连续两页全部早于窗口时按观测边界停止（非一致性快照）。达到上限/重复页/失败明确部分覆盖。

中文 Jieba 分词、校园词典、停用词；每词每帖只计一次 DF。DF>=3 的词形成候选热词；近期正文 TF-IDF 余弦相似度作辅助主题归并。互动独立召回：各指标非零样本排名前 10% 且满足最低计数（收藏 5、点赞 3、评论 10，均可配置）。收藏/点赞/评论各保留一个达标代表帖，剩余并集候选按话题 0.4/互动 0.5/新鲜度 0.1 排序；互动默认收藏 0.4/点赞 0.3/评论 0.3，缺失指标记 null 并重分配可用权重。若不足 30 个可填充有正文帖子，标注补充样本而非声称热点。

评论仅对入选帖分页抓取；从第一页刷新，保留预览作为失败备份；按 cid 去重；最大 200 页/帖可配置，保留失败与计数差异。父节点优先本帖 cid 精确匹配，再使用同帖 quote；未知父节点明确缺失，不跨帖关联匿名身份。统计截止时刻固定，评论作为抓取时讨论快照保留采集时间。

## 产物与模型
先原子保存 posts.json（正文、评论、关系、评分、运行参数与覆盖情况）和 sources.md，再调用模型。总结分为有预算的素材分块笔记与最终汇总；无长材料时直接汇总。引用使用 [#pid] / [#pid/cid]；模型只得到素材和指令，不获检索/执行工具；校验未知引用，输出标明来源及部分采集。超出模型预算时记录未覆盖块，不静默截断。默认最多 40 次笔记调用，最终 1 次；单次流式 120 秒沿用已有模型调用。失败保留素材和错误状态，支持 --hot-replay 从本地 JSON 重试；--hot-only 导出不调用模型。

新增配置有默认值，兼容原有 config_private.py。无配置时给出清晰本地配置方法，不导入缺失 config.py。仅模式 4 使用新的严格模型错误处理，旧模式不做无关重构。真实数据/凭据不提交。

## 验收
离线测试覆盖 API 参数、分页/去重/缺失字段/限流/失败、词频防刷、排名与并集、评论多层关系和缺失父节点、先导出再总结、重放、长上下文和模型错误。模式 1～3 做无网络回归。真实登录后抽查 10 帖计数/评论/出处；离线通过与真实通过分别记录。用户在本地验收后才推送 PR 并合并其 fork，原仓库 PR 由用户处理。

## 真实联调后的修订
- comment_total 和 data.total 是分页提示；reply 才用于评论数量评分和完整性比较。
- 官方 DeepSeek 接口的模式 4 默认关闭 thinking，保持原模型和输出额度，避免推理耗尽输出上限；自定义地址不默认发送该参数。
- 引用白名单来自结构化记录，评论片段可引用所属帖子与有原文证据的父评论；正文自带洞号不自动获得引用资格。
- 每份笔记/最终总结的无效引用最多纠正一次，所有调用（包括纠正）合计不超过 HOT_MAX_SUMMARY_CHUNKS+1。失败草稿作为本地诊断保留，不能当作正式报告。
